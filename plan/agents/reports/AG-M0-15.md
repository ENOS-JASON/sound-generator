# AG-M0-15 — Fast component approximations

**Status: partial; implementation submitted for CI and owner review.**

- Prerequisites: AG-M0-03 (VehicleDefinitionV2 / SI) and AG-M0-04 (component identity and physical-port SI units) are complete on main. No dependency on the still-open runtime-owner ADR-001.
- Additive version-1 proposal in `src/contracts/approximation/index.ts`; registry in `src/approximations/ApproximationRegistry.ts`. No existing public contract, solver, event, dependency or deployment changes. The new public contract requires owner review before freeze.
- A registered analytic kernel can serve multiple compatible component bindings with distinct parameters. Optional component-specific, versioned coefficient sets or bounded 1D additive correction maps can select trained behavior; invalid provenance, versions, domains, bounds or outputs return the checked analytic baseline with an explicit reason. Invalid physical inputs or incompatible units/basis are rejected rather than coerced. Imported data cannot supply executable kernels.
- Reference adapters provide a versioned common SI projection with component/context identity, run/tick, source version and uncertainty. This checks compatibility and numeric bounds; it does not implement a high-fidelity solver or establish reference truth.
- The fixture uses illustrative arithmetic, not a validated fluid model. It covers two bindings, coefficient/lookup activation, domain/identity fallback, invalid outputs/units and reference projection. Numerical conservation beyond the registered invariant, actual calibration data, multidimensional maps, verified hashes, hot-path performance and solver integration remain future work.
- Intended validation: existing `npm run check` (typecheck, lint, format, unit tests, build) and Pages Chromium smoke. No checks are claimed passing until CI provides evidence. Complete and roadmap boxes remain unchanged.
