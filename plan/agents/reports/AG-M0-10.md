# AG-M0-10 — Clock and solver-location benchmark handoff

**Status: PARTIAL.** Prerequisites AG-M0-03 and AG-M0-09 are complete. The fixed-step clock and synthetic benchmark are implemented; no final solver location or pitch-preserving DSP is selected or claimed. ADR-001 is open pending primary desktop evidence and explicit owner approval. PR [#12](https://github.com/ENOS-JASON/sound-generator/pull/12) is a partial implementation.

## Implementation

- 1 kHz integer-phase simulation clock maps ticks to sample boundaries. Scale range 0–1 with 0.000001 resolution, paused bounded manual stepping (10,000 ticks maximum), independent physical and pitch-preserved mode selection and canonical diagnostic/control envelopes. Scale >1 remains unbenchmarked and rejected. Scheduler and command deduplication are outside this card's fixture.
- Both browser locations call the same seeded synthetic I4 starter/manual/road-load solver and impulse generator. Worker transport is a bounded four-block lookahead over MessagePort. Silence on queue starvation is counted; physical blocks are not skipped. The event hash excludes playback frame references; PCM hash covers padded synthetic blocks, not inserted underrun silence.
- Timing measurements are proxies: solver computation elapsed time, callback interval jitter, main-to-solver ping round trips, Worker block round trips, startup and main elapsed time, queue underrun frames and audio clock gaps. If a worklet lacks a monotonic performance timer, corresponding statistics are explicitly null. Actual device underruns, process CPU utilization, GC/memory and one-way control-to-audio latency are not proven by these metrics. The mock is not a calibrated engine.

## Desktop benchmark instructions

After deployment, open https://enos-jason.github.io/sound-generator/src/testing/mock-solver/benchmark.html .

Alternatively, from the PR branch run `npm ci`, `npm run build`, `npm run preview`, then open `http://localhost:4173/sound-generator/src/testing/mock-solver/benchmark.html`. Keep the tab visible, use an active audio output, enter exact OS, CPU/GPU, browser build and audio-device/driver details, and download JSON after each test. No recording is uploaded automatically.

Run each combination of 44.1/48 kHz and 1x/0.1x, repeating in reverse execution order at least once. Each comparison advances 3 simulated seconds. Do not use `?smoke` for hardware evidence; that is a shorter functional browser smoke only. Record browser task-manager CPU/memory, device audio settings, browser performance traces and audio interruptions separately. Report null timing fields, suspension, gaps, underruns and failed/mismatched runs rather than discarding them.
