# ADR-002 — Svelte UI major, hash router and state conventions

**Status: PROPOSED — owner approval required.** Owner-approved constraints are Svelte + Vite, strict TypeScript and hash routes under the GitHub Pages subdirectory (UD-R1-03, UD-R2-02). This proposal **does not freeze** the remaining major choices.

## Proposed choices for AG-M0-01

1. **Svelte 5 with Vite 8:** use current compatible major releases, pinned exactly in the initial package manifest. Prefer Svelte's built-in reactivity and avoid a second framework.
2. **Router:** begin with a small, pure hash-route resolver for the foundation fixture. Decide with the owner whether to retain a typed in-house hash router or adopt a version-pinned third-party hash router before AG-M0-14a. Never use history routing on Pages.
3. **Shared state:** page-local Svelte 5 reactivity for this placeholder shell only. Proposal for future shared runtime: explicit owner-controlled service instance + readonly UI projections, not per-page engine instances. Decide with owner whether built-in Svelte stores/runes suffice or a named external state library is required.
4. **UI components:** no component framework selected. Keep the initial shell semantic and accessible. Component-framework choice requires separate owner review if major.

## Tradeoffs / alternatives

- **Small hash resolver:** zero additional runtime dependencies and direct-link compatibility; it lacks nested/parameterized routing, guards and navigation lifecycle. A dedicated router adds ecosystem semantics but must be pinned and tested.
- **Built-in state:** smaller dependency surface; requires disciplined runtime ownership and lifecycle testing. A third-party store could add tooling/structure but also introduces a major architectural dependency.
- **Svelte 5:** uses current runes and an established Vite integration; major-version choice must receive owner approval before later UI contracts depend on it.

## Evidence and change boundaries

The scoped positive/negative hash fixtures are in `tests/fixtures/hash-route-cases.json` and `tests/routing.test.mjs`. The Vite `base` is configured outside components. This ADR does **not** create `src/contracts`, a shared runtime, a public router interface or an accepted schema.

**Affected work orders:** AG-M0-01, AG-M0-02, AG-M0-14a/b, AG-M0-18 and downstream M3 UI cards.

**Owner decision required:** approve Svelte 5/Vite 8 and select (a) simple hash router vs third-party hash router, (b) built-in shared Svelte stores/runes vs external state library, and (c) defer or name any UI component framework. Only then update this ADR to Accepted with attributable decision and run evidence.
