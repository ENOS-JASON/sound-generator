# ADR-003 - Canonical vehicle data and import boundary

**Status: PROPOSED - requires project-owner review and merge of AG-M0-03 PR.**

## Proposed decision

- Canonical `VehicleDefinitionV2` and `ComponentManifestV2` use `schemaVersion: 2` with strict JSON Schema Draft 2020-12 and a single TypeScript validator for all future entry points.
- All physical quantities are SI internally. Boundary conversion functions explicitly name units; the seeded Mulberry32 PRNG has deterministic `uint32` seed and is never used for cryptographic security.
- Two exclusive I4 structural variants: `mechanical` references carburetor+distributor and no ECU; `ecu` references EFI+ECU+coils and fuel/spark map IDs. Mixed controllers and orphan components fail validation.
- Starter must link the battery and engine, and the manual powertrain must reference an engine, clutch, gearbox, axle and road load. Engine cylinder IDs and firing order are validated as a permutation; only finite bounded geometry is accepted.
- The structural `EngineEventEnvelopeV2` carries run ID, sequence, sim tick/seconds, source, causation and correlation IDs, plus bounded JSON payload. AG-M0-09 owns typed events/commands, clock transport and semantic sequencing.
- Unknown versions are rejected. **Legacy v1 has no automatic migration:** the illustrative v1 preset lacks controllers and required physical topology. A future versioned migration requires explicit defaults, safe UI review and separate tests; otherwise import returns a clear rebuild-required error.

## Rejected alternatives and limitations

Do not silently infer missing legacy parts, choose an ECU as a fallback, hard-code a factory default over an IndexedDB workspace, accept unknown component families, or pretend a schema-valid preset is runnable. Detailed port graphs, support registries and power/energy signs belong to AG-M0-04, geometry-derived volume to AG-M0-07 and physical parameter approval and executable presets to AG-M1-12.

The fixtures deliberately mark each component `planned`; structural acceptance is **not** proof of physical simulation, audio, benchmark, numerical accuracy, licensed measurements or calibrated realism.
