# ADR-008 — Port graph and technology support representation

**Status: PROPOSED for owner review in [PR #6](https://github.com/ENOS-JASON/sound-generator/pull/6); not accepted before owner review/merge.**

## Decision proposed

Use an additive `PortGraphV1` interface alongside the already accepted `VehicleDefinitionV2`, not a schema replacement or automatic migration. Each component has stable IDs, a provider ID/version, an operating domain, a support status and typed port endpoints. Graph connections are explicit; the registry declares which capabilities/fidelity levels the provider actually supports in each operating domain.

- Port kind: rotational, electrical, air, fuel, exhaust gas, thermal and control. Each declares exact canonical SI effort/flow pairs, directed link semantics and required/cardinality constraints. Gases require explicit absolute/gauge pressure basis; controls require a matching signal type. Control ports never imply energy flow.
- Each component/domain is separately `implemented`, `approximate`, `planned` or `unsupported`. A planned/unsupported model is visible to configuration tools but cannot be instantiated; no implicit substitution by a four-stroke engine or ECU.
- Signed rotational power **into** a component is `T_on_component_Nm × omega_rad_s`. A shaft that exports power has negative port-input power. Link residual is the sum of endpoint powers plus declared dissipation and energy storage rate; ideal links balance within explicit tolerance.
- Bank/cylinder topology preserves physical bank identity and 1–12 cylinder IDs and exposes 720-degree four-stroke phase offsets. Actual crank geometry, irregular firing intervals and coupled numerical solver remain M0-07/M1 responsibilities.

## Tradeoffs and compatibility

The versioned graph v1 complements, rather than embeds itself into, the rigid v2 import model. Compatibility adapters from v2 to future runnable graphs are not part of this task. A mock graph fixture verifies the contract without claiming physical models. No technology accuracy, engine dyno output or solver integration is certified by this decision. The proposed per-run registry and test harness use explicit factories and reject missing capabilities.
