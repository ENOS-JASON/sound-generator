# ADR-004 — Event dictionary, ownership and control-plane aliases

**Status: PROPOSED — owner review and verified merge required.** Implements the direction in [11](../11-event-bus-and-messaging.md), [24](../24-simulation-clock-and-time-scaling.md) and [30](../30-agent-handoff-contracts-and-decisions.md). Does not choose the Worker versus AudioWorklet solver owner.

## Proposed contract

- Preserve accepted structural v2 and its strict validator/schema. The typed event envelope is **v3**, with an explicit domain/diagnostic category and optional integer sample frame and finite unwrapped crank angle. Keep sourceComponentId, runId, causation/correlation and SI simulation time. Payload catalog is the single typed/runtime dictionary; unknown types/fields are rejected. Payloads are flat immutable values at this stage.
- Domain EventMap represents physical facts, with one increasing sequence per run and a trusted source-component-to-role registry; UI, audio, scenarios and renderer cannot publish physical transitions. DiagnosticMap has an independent category sequence, never fills a domain gap. IDLE_CONTROL_CHANGE and continuous sensor/voltage/pressure samples are state projections.
- Commands v1 use unique commandId, origin, target simulation tick and optional target sample frame, causal references and typed SI payloads. Acceptance, rejection and application are distinct diagnostic messages. Command scheduling, idempotent application and non-reentrant dispatch belong to M1, not this card.
- Explicit **v2 import-only** aliases REV_LIMIT_ENTER/EXIT -> LIMITER_ENTER/EXIT and CLOCK_PAUSED/RESUMED -> RUN_PAUSED/RESUMED. Canonical live v3 rejects aliases; migration rejects unknown types or invalid payloads. The per-event adapter preserves IDs and sequence; a mixed historical log must be separately validated/resequenced by category, not silently treated as a contiguous domain trace.
- DomainBatch v1 uses a bounded receiver (configurable 1–1024 events per batch; proposed defensive ceiling, not measured throughput). Same-tick events retain sequence and sim time. Stale-run batches and fully delivered duplicate batches do not advance the cursor; overlap/gap, regressing clock, malformed event or unauthorized owner invalidates atomically. Overflow is explicit QUEUE_OVERFLOW; other invalid streams surface EVENT_STREAM_GAP. An invalid cursor cannot resume until authoritative resynchronization; actual resync belongs to the runtime.
- Critical messages and coalescible snapshots have distinct transport and subscription interfaces. MessagePort, AudioWorkletNode.port and local implementations must honor bounded limits, explicit overflow/closed outcomes, run/sequence checks and teardown. No SharedArrayBuffer requirement. No transport allocation or timing claim is made.

## Owner review

New event/command identifiers, payload shapes, component roles, v3 category and defensive batch ceiling are public contract proposals under O3-15 B; owner review and merge is sufficient approval. The precise command scheduler, full snapshot schema/validation, recording migration, real queue implementation, browser transport and performance remain later work.
