## Round 1 owner decisions — audit disposition

- **A01 remains OPEN:** equivalent AudioWorklet-owned and Worker-owned solver benchmarks followed by explicit project-owner selection. Do not pick a default solver owner.
- **A02 partially resolved:** **Svelte + Vite approved**; router/store and version choice still open.
- **A07 extended:** **both pitch-lowered and pitch-preserving slow motion are required**, with a selectable mode. Default and DSP quality/error budget still open.
- **A11/A12 clarified:** interface must accommodate eventual **actual 3D CFD, chemistry and material models** and validated **native CPU/GPU/other numerical compute backends**. Initial M6 research is not thereby a validated 3D CFD solver.
- **A17/A24 clarified:** first completely running baseline must be **I4 gasoline, starter, basic manual clutch/gearbox and vehicle/road load**. ECU/carb details still pending.
- **Cross-cutting owner policy:** every major architecture change/choice is proposed to and approved by the project owner, not automatically accepted by a coding agent. See [Round 1](decisions/USER-APPROVED-ROUND-01.md).

## What to do if documentation disagrees

1. Stop and cite the two contradictory statements in the task result. Do **not** privately pick one.
2. Check an accepted decision record and normative schema in [30](30-agent-handoff-contracts-and-decisions.md), then task-specific phase brief in [agents/README](agents/README.md).
3. If still unresolved, produce a small **blocking contract-change proposal** with candidate options and affected tasks. Do not implement against guessed event names, clocks, codec or port signs.
4. A document's `planned` feature list is not permission to implement it during another agent's work order.
5. Source docs are linked for **details relevant to the assigned card**; agents need not re-read all 29+ design files.

## Audit conclusion / task-handoff changes

The existing plan covers most **feature categories**. The gap is **execution specificity**: ambiguous ownership, contract versioning, integration sequence, acceptance fixtures, and independently reviewable assignments. The next agents should operate from the task cards, not interpret each roadmap bullet as an implementation specification. Every discovered contradiction is recorded here and must be resolved by a named contract owner or a testable boundary before parallel development.
